# AJAX 입문 정리

## 1) AJAX란 무엇인가

**정의**: **AJAX**(Asynchronous JavaScript and XML)는 _웹 페이지를 새로고침하지 않고_ **JavaScript로 서버와 데이터를 비동기적으로 주고받는** 방식 전반을 가리키는 용어입니다.
**한 문장 요약**: 화면은 그대로 둔 채, 서버와 데이터를 주고받아 **동적 UI를 빠르게 갱신**하는 기술 묶음입니다.

- 과거에는 데이터 포맷으로 **XML**을 자주 썼기에 이름에 XML이 들어갔습니다.
- 오늘날에는 **JSON** 사용이 더 일반적입니다.

---

## 2) 왜 필요한가 (동적 웹과 비동기 통신)

### 동적 웹 요구

- **JavaScript** 덕분에 버튼 클릭, 스크롤 등 사용자 동작에 따라 화면을 즉시 바꿀 수 있습니다.
- 이를 위해서는 **서버와 데이터를 주고받는 능력**이 필요합니다.

### 실전 예시 흐름

- **좋아요 버튼**

  1. 사용자가 버튼 클릭 →
  2. JavaScript가 서버로 **요청(request)** 전송(“좋아요 증가”) →
  3. 서버가 **응답(response)** 으로 결과를 돌려줌 →
  4. 페이지를 새로고침하지 않고 버튼 상태/개수를 **즉시 갱신**.

- **무한 스크롤(SNS 피드)**

  1. 사용자가 아래로 스크롤 →
  2. 특정 지점에 도달하면 JavaScript가 **추가 데이터 요청** →
  3. 응답으로 받은 새 콘텐츠를 **페이지 하단에 삽입**하여 계속 스크롤 가능.

### 비동기(async)의 필요성

- 네트워크 **응답 대기 시간**은 길어질 수 있습니다.
- **비동기 처리**를 쓰면, 응답을 기다리는 동안 **다른 JS 코드가 계속 실행**되어 브라우저가 멈추지 않습니다.
  → 사용자는 **끊김 없는** 인터랙션을 경험합니다.

## 3) AJAX 구현 수단(역사와 현재)

### 3-1) XMLHttpRequest (XHR)

- **초기 AJAX 구현 수단**으로, **페이지 새로고침 없이** 요청/응답을 처리할 수 있어 큰 인기를 끌었습니다.
- 다만 **문법이 복잡**하고 **직관성이 떨어지는 경우**가 있었습니다.

### 3-2) fetch

- **표준 Web API**로, **요청을 쉽게 보낼 수 있고** **Promise 기반**이라 비동기 처리가 **깔끔**합니다.
- 오늘날 **JavaScript로 요청을 보내는 정석적인 방법**으로 널리 사용됩니다.

### 3-3) axios

- **fetch와 문법은 비슷**하지만, **요청/응답을 다루는 방식이 조금 다르며**
  **실무에 유용한 편의 기능**을 제공합니다.
- 따라서 **웹 개발 시 큰 도움이 되는 도구**로 소개됩니다.

## 5) 용어 한 줄 정리

- **AJAX**: 새로고침 없이 서버와 **비동기 통신**을 수행해 화면을 빠르게 갱신.
- **비동기(Asynchronous)**: **응답을 기다리는 동안에도** 다른 JS 작업을 계속 실행.
- **Request/Response**: 클라이언트가 서버에 **요청**을 보내고 **응답**을 받는 과정.
- **XML → JSON**: 과거에는 XML, 현재는 **JSON**이 더 널리 쓰임.
- **XMLHttpRequest(XHR)**: 초기 AJAX의 핵심 도구이지만 **문법이 다소 복잡**.
- **fetch**: **표준 Web API**, **Promise 기반**으로 비동기 요청을 **간결하게 처리**.
- **axios**: fetch와 유사하되, **편의 기능**으로 **실무 활용성**이 높음.
