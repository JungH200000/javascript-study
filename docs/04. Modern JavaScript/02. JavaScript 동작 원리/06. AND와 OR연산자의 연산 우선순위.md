# AND와 OR 연산자의 연산 우선순위

> **정의 한 줄 요약**: JavaScript의 `&&`(AND)와 `||`(OR)은 **피연산자 중 하나를 그대로 반환**하며, **우선순위는 `&&`가 `||`보다 높다**. 괄호로 의도를 명확히 하면 예측 가능성이 높아진다.

---

## 1) 예시 함수로 보는 맥락

```js
function checkAnswer(value) {
  if (value < 10 && value > 0 && value != 3) {
    return '정답입니다.';
  }

  return '틀렸습니다.';
}

console.log(checkAnswer(4));
```

- 조건식에서 `&&`를 **여러 번 연달아** 쓰는 경우에는 왼쪽부터 차례로 평가해도 **의도와 결과가 일치**한다.
- 하지만 **`&&`와 `||`를 섞어** 쓰면 **연산자 우선순위** 때문에 결과가 달라질 수 있으므로 **괄호로 의도**를 분명히 하는 습관이 필요하다.

---

## 2) 왜 우선순위가 중요할까?

- 산술에서 `1 + 2 * 3`에서 `*`가 `+`보다 먼저 계산되는 것처럼,
  **논리 연산자도 우선순위가 있다.** 이때 **`&&`가 `||`보다 먼저** 평가된다.
- JavaScript의 논리 연산자는 **항상 불린을 반환하지 않고**, **상황에 따라 양쪽 값 중 하나를 반환**한다.
  따라서 **평가 순서(우선순위)** 에 따라 **최종 결과 값**이 달라진다.

---

## 3) 괄호 유무에 따른 결과 차이

```js
console.log(true || (false && false)); // true
console.log((true || false) && false); // false
console.log('Hello' || (NaN && false)); // Hello
console.log(('Hello' || NaN) && false); // false
```

- 첫 번째 줄: `false && false`가 먼저 `false`가 되고, `true || false` → `true`.
- 세 번째 줄: `NaN && false`는 `NaN`을 반환하고, `'Hello' || NaN` → `'Hello'`.

> **포인트**: 같은 피연산자라도 **괄호 배치**에 따라 `&&`가 먼저 계산될지, `||`가 먼저 계산될지가 달라져 **최종 값이 달라질 수 있다.**

---

## 4) 협업을 위한 좋은 습관

- 다양한 연산자를 **복합적으로 사용할 때는 괄호**를 사용해 **의도한 평가 순서**를 분명히 표기하자.
- 연산 순서를 헷갈리거나 예상과 다른 결과가 나오면 **연산자 우선순위 표**를 참고하자.
  [연산자 우선순위](https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Operators/Operator_precedence)

---

## 5) 추가 예시

```js
console.log(true || (false && false)); // true
console.log((true || false) && false); // false

console.log('Codeit' || (NaN && false)); // Codeit
console.log(('Codeit' || NaN) && false); // false
```

- 위 블록 역시 **괄호 유무**로 인해 **평가 순서**가 바뀌면 결과가 달라짐을 보여준다.

---

## 핵심 요약

- **우선순위**: `&&`가 `||`보다 **먼저** 평가된다.
- 논리 연산자는 **불린이 아니라 피연산자 값 자체**를 반환할 수 있다.
- **괄호**로 의도를 명확히 하지 않으면 **예상과 다른 결과**가 나올 수 있다.
- 결과가 헷갈리면 **우선순위 표**를 확인하고 **괄호 사용**을 습관화하자.
