# Rest Parameter

함수 내부에서 arguments 객체를 활용하면 불규칙하게 argument가 전달되는 상황에서도 유연하게 argument들을 다룰 수 있다.

그런데 arguemnts 객체에도 몇 가지 아쉬운 부분들이 있는데

1. arguments 객체가 유사 배열이기 때문에 배열의 메소드 사용 불가
2. 항상 함수 호출 시 전달한 argument 전체를 다루기 때문에 일부분만 다루려면 인덱싱을 통해서 한 번 더 세분화하는 과정이 필요

그런데 이 ES2015 이후에 이런 arguments 객체의 아쉬움을 해결해주는 Rest Parameter라는 문법이 등장하게 되었다. 지금부터 어떤 문법인지 살펴보자.

Rest Parameter 문법은 생각보다 간단한데, arguments 객체를 활용한 코드를 가지고 Rest Parameter를 이용한 코드로 변경해보겠다.

이용 전

```js
function printArgument(a, b, c) {
  for (const arg of arguments) {
    console.log(arg);
  }
  console.log('--------------');
}

printArgument('JavaScript');
printArgument('Jav', 'Hyun', 'Chung', 'Lee');
printArgument('Ha', 'Ah');
```

이용 후

```js
function printArgument(...args) {
  for (const arg of args) {
    console.log(arg);
  }
  console.log('--------------');
}

printArgument('JavaScript');
printArgument('Jav', 'Hyun', 'Chung', 'Lee');
printArgument('Ha', 'Ah');
```

파라미터 하나를 만들어서 그 앞에 `...` 마침표 3개를 붙여준 것이다. 그러면서 arguments 객체 대신 해당 파라미터를 사용한 것. 코드의 실행 결과를 보면 arguments 객체의 실행 결과가 동일하다.

이렇게 일반 파라미터 앞에 `...` 마침표 3개를 붙여준 것을 Rest Parameter라고 한다. Arugmets 객체는 유사 배열이기 때문에 배열의 메소드는 사용할 수 없지만 반면에 Rest Parameter는 배열이기 때문에 배열의 메소드를 자유롭게 사용할 수 있다.

```js
function printArgument(...args) {
  console.log(args.splice(0, 2));
  console.log(arguments.splice(0, 2));

  console.log('--------------');
}

printArgument('JavaScript');
printArgument('Jav', 'Hyun', 'Chung', 'Lee');
printArgument('Ha', 'Ah');
```

위 코드를 실행하면 `args.splice(0, 2)` 이 부분에서는 0번부터 요소 2개가 잘 나온 것을 볼 수 있고, `arguments.splice(0, 2)` 부분은 Error 메시지가 출력된다.
(Uncaught TypeError: arguments.splice is not a function)

```js
function printRank(first, second, ...others) {
  console.log('경시대회 최종 결과');
  console.log(`대상: ${first}`);
  console.log(`금상: ${second}`);
  for (const other of others) {
    console.log(`참가자: ${other}`);
  }
}

printRank('Chung', 'Ji', 'Hyun', 'Jung', 'Hak');
```

그리고 Rest Parameter는 일반 파라미터와 함께 사용할 수 있다. Rest라는 이름처럼 앞에 정의된 파라미터에 argument를 먼저 할당하고 나머지 argument를 배열로 묶는 역할을 하기 때문에 일반 파라미터와 함께 사용할 때는 가장 마지막에 작성되어야 한다.

항상 전달된 모든 argument를 다루는 arguments 객체와는 다르게 위 코드처럼 명확하게 구분해서 다뤄야 하는 부분은 일반 파라미터를 사용하고 유연하게 다룰 수 있는 부분은 Rest Parameter로 나눠서 필요에 따라 부분적으로 유용하게 활용할 수 있다.

대부분의 상황에서 Rest Parameter가 가지는 장점이 상대적으로 더 크기 때문에 코드를 작성할 때 가급적이면 Rest Parameter를 우선적으로 활용하고 불가피한 상황에서 arguments 객체를 활용하는 것이 많은 스타일 가이드에서 권장하는 방법이기도 하다. 하지만 ES2015 버전이 나오기 전에는 불가피하게 arguments 객체가 사용되기도 했고 상황에 따라서는 Rest Parameter가 argument 객체를 100% 완벽하게 대체할 수 없기 때문에 두 가지 모두 잘 이해하고 차이도 명확히 이해하는 것을 권장한다.
