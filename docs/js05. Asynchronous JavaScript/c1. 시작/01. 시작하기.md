# 비동기 프로그래밍 시작하기 (JavaScript)

**정의(한 줄 요약):**
오래 걸리는 작업이 있으면 그동안 **다른 일을 먼저 처리**하고, 작업이 끝나면 **다시 돌아와 마무리**하는 실행 방식.

웹 요청처럼 시간이 많이 드는 일을 “그냥 기다리기만” 하면, 그 사이에 처리할 수 있었던 수많은 연산 기회를 놓칩니다. 효율적인 프로그램은 **기다림 동안 다른 작업을 진행**하고, **완료 신호가 오면 다시 이어서 처리**합니다. 이것이 문서 전반이 말하는 **비동기 프로그래밍의 핵심 아이디어**입니다.

JavaScript는 본래 웹을 위해 만들어졌고, **요청/응답 대기**나 **사용자 상호작용 대기**가 많기 때문에 비동기 프로그래밍이 널리 쓰입니다. React, Express와 같은 기술 스택 곳곳에서도 이러한 개념이 자연스럽게 등장합니다. 앞으로 다양한 JS 기술을 다루려면, 비동기 개념을 이해하고 있어야 합니다.

---

## 느린 작업의 예: 네트워크 요청

아래 코드는 “오래 걸릴 수 있는 작업”의 전형적인 예로 **웹 요청**을 보여줍니다.

```js
response = sendRequest('https://...');
```

### 코드 해설

- `sendRequest('https://...')`
  서버로 **요청(request)** 을 보냅니다. 요청이 서버에 도달하고, 서버가 처리한 뒤 **응답(response)** 이 돌아오기까지 시간이 걸릴 수 있습니다.
- `response = ...`
  요청 결과를 **응답 값**으로 받습니다. 이 응답을 받기 전까지는 프로그램이 **오래 기다릴 수도** 있습니다 — 문서가 강조하듯, 이 기다림 동안 “다른 일”을 먼저 처리할 수 있으면 더 효율적입니다.

> 요점: **네트워크 왕복은 느릴 수 있다** → **그 시간에 다른 일을 처리**하도록 프로그램 구조를 짜는 것이 비동기의 목적입니다.

---

## 왜 비동기가 필요한가

- **기다림 자체는 생산적이지 않다.**
  응답을 멍하니 기다리는 대신, **다른 연산을 먼저 수행**하면 전체 처리량이 늘어납니다.
- **효율적인 흐름으로 전환한다.**
  오래 걸리는 작업을 시작해두고, **다음 작업을 계속** 진행합니다. **완료되면 다시 돌아와 마무리**합니다.
- **JS 환경과 잘 맞는다.**
  웹 개발은 요청/응답, 사용자 입력 등 **대기 상황이 빈번**합니다. 그래서 JS 세계(예: React, Express)에서 비동기 개념이 **자주 등장**합니다.

---

## 앞으로 다룰 핵심 도구

- **Callback(콜백)**, **Promise(프로미스):** **비동기 코드를 작성할 때 사용하는 두 가지 방식/도구**입니다.

---

## 핵심 요약

- **비동기 프로그래밍**은 오래 걸리는 작업 동안 **다른 일을 먼저 처리**하고, 완료되면 **다시 이어서 처리**하는 방식입니다.
- **웹 요청**은 대표적인 느린 작업으로, JS에서는 이런 대기 상황이 흔합니다.
- 비동기를 잘 쓰면 **전체 효율**이 올라갑니다.
- JS 생태계(React, Express 등)에서는 비동기 개념이 **자주 등장**합니다.
- 이어서 **콜백과 프로미스**를 통해 비동기 코드를 **어떻게 표현하는지** 살펴볼 예정입니다.
