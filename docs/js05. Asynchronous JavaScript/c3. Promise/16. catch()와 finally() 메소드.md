# `.catch()`와 `.finally()` 메소드

**정의(한 줄 요약)**

- **`.catch(onRejected)`**: 앞선 Promise 체인에서 **거부(Rejected)** 가 발생하면 **오류를 인자로 콜백을 실행**하고, **새 Promise**를 반환한다.
- **`.finally(onFinally)`**: 앞선 Promise가 **성공/실패와 상관없이** 콜백을 **항상 실행**하고, **원래의 상태/결과를 그대로 다음으로 전달**하는 새 Promise를 반환한다.

---

## 1) `then` 체인에 `catch`/`finally` 추가

```javascript
// main.js
fetch('https://learn.codeit.kr/api/employees')
  .then((response) => response.json()) // 응답 본문 파싱 (Promise 반환)
  .then((data) => console.log(data)) // 파싱 결과 출력
  .catch((error) => console.log('Error!')) // 어디서든 거부되면 여기서 처리
  .finally(() => console.log('Finished!')); // 항상 마지막에 실행

console.log('Task 2');
console.log('Task 3');
```

### 실행 결과(정상 요청)

```terminal
Task 2
Task 3
[
  {
    id: 1,
    name: 'Jason',
    email: 'jason@codeitmall.kr',
    department: 'engineering'
  },
  ...
  {
    id: 10,
    name: 'Alex',
    email: 'alex@codeitmall.kr',
    department: 'sales'
  }
]
Finished!
```

### 실행 결과(잘못된 URL 등으로 실패 시)

```terminal
Task 2
Task 3
Error!
Finished!
```

- **비동기 대기 중**에는 아래의 **동기 코드**(`Task 2`, `Task 3`)가 먼저 실행된다.
- 체인 어디에서 오류가 나든 **Rejected가 전파**되어 `.catch()`가 실행된다.
- `.finally()`는 **항상** 마지막에 실행된다.

---

## 2) `try…catch…finally`와의 대응

```javascript
async function printEmployees() {
  try {
    const response = await fetch('https://learn.codeit.kr/api/employees');
    const data = await response.json();

    console.log(data);
  } catch (error) {
    console.log('Error!');
  } finally {
    console.log('Finished!');
  }
}

printEmployees();

console.log('Task 2');
console.log('Task 3');
```

- 의미적으로 **`.then().catch().finally()` 체인**과 **`try…catch…finally`** 는 동일한 흐름을 표현한다.

---

## 3) 동작 원리(체인 내부 흐름)

```javascript
// main.js
fetch('https://learn.codeit.krError/api/employees') // 의도적 오류: 잘못된 주소
  .then((response) => response.json()) // (A) 성공 시에만 실행
  .then((data) => console.log(data)) // (B) 이전이 성공해야 실행
  .catch((error) => console.log('Error!')) // (C) 거부되면 여기서 처리
  .finally(() => console.log('Finished!')); // (D) 항상 실행

console.log('Task 2');
console.log('Task 3');
```

1. **모든** `fetch`/`then`/`catch`/`finally`는 **Promise를 반환**한다.
2. `fetch`가 **대기(Pending)** 인 동안 아래의 동기 코드(`Task 2`, `Task 3`)가 먼저 실행된다.
3. 잘못된 주소로 인해 `fetch`의 Promise가 **Rejected**가 되면, 첫 번째 `.then`은 **콜백을 실행하지 않는다**.

   - 이어지는 다음 `.then`도 **계속 Rejected를 전달**받아 콜백을 실행하지 않는다.

4. `.catch`는 **직전까지 전파된 Rejected**를 **인자로 받아 콜백 실행**: 여기서는 `'Error!'` 출력.

   - 콜백이 **일반 값을 반환**하면, 이 `.catch`가 돌려주는 Promise는 **Fulfilled**가 된다.

5. `.finally`는 **앞선 Promise가 Fulfilled/Rejected 중 무엇이든** **항상 콜백을 실행**한다.

   - 그리고 **원래의 상태/결과를 그대로 다음으로 전달**한다.
   - (즉, `finally` 콜백이 **오류를 던지지(throw)** 않거나 **거부된 Promise를 반환**하지 않는 한, 이전의 **성공/실패 상태가 유지**된다.)

> 정리:
>
> - **`.then`**: 앞 단계가 **성공(Fulfilled)** 일 때만 콜백 실행.
> - **`.catch`**: 앞 단계가 **실패(Rejected)** 일 때만 콜백 실행.
> - **`.finally`**: **항상 실행**, 단 **체인의 상태/값은 기본적으로 그대로 통과**(콜백에서 새 오류를 던지면 그때 거부로 바뀜).

---

## 4) 핵심 포인트 정리

- **체인 전파**: Rejected는 **다음 `.then`들을 건너뛰며** `.catch`까지 **전파**된다.
- **`.catch`의 반환**: 콜백이 **일반 값**을 반환하면 **Fulfilled**로 전환되어 다음 단계로 이어진다.
- **`.finally`의 역할**: **항상 실행**하며, **기본적으로 이전 상태/결과를 보존**한다(콜백에서 오류를 던지면 거부로 변경).
- **실행 순서**: 비동기 대기 중에는 **아래의 동기 코드**가 먼저 실행되고, 완료되면 **체인으로 복귀**한다.
