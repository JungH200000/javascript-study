# Symbol과 BigInt

- **공통 요약**: 둘 다 **기본형(primitive)** 타입이다. `Symbol`은 **유일한 값**을 만들고, `BigInt`는 **아주 큰 정수**를 안전하게 표현한다.

---

## 1) Symbol

> **정의**: `Symbol`은 **서로 절대 같아질 수 없는 고유한 값**을 만드는 기본형 타입.
> **한 문장 요약**: **설명(text description)이 같아도 값은 항상 서로 다르다.**

### 예시 코드

```javascript
// Symbol() 함수를 통해 심볼 값을 만들 수 있다.
const example = Symbol();

const symbolA = Symbol('this is a user');
// 괄호 안에 심볼에 대한 설명(디스크립션)을 붙일 수 있다.
// 이 설명은 디버깅용 메타 정보일 뿐, 심볼의 동등성에 영향을 주지 않는다.

console.log(symbolA === 'this is user'); // false
console.log(symbolA === 'user'); // false
console.log(symbolA === true); // false

// 똑같은 설명을 붙인 심볼을 만들더라도 두 값은 항상 다르다.
const symbolB = Symbol('this is a user');

console.log(symbolA === symbolB); // false
console.log(symbolA === 'this is a user'); // false
```

### 코드 해설 (핵심 포인트)

- `Symbol()` 호출 → **새로운 고유 값** 생성.
- `Symbol('...')`의 **문자열은 설명**일 뿐이며, **동등 비교에 영향 없음**.
- 어떤 **다른 타입(문자열/불리언 등)** 과 비교해도 `===` 결과는 `false`.
- **같은 설명으로 만든 두 심볼**도 `===` 비교 시 **항상 `false`**.

## 2) BigInt

> **정의**: `BigInt`는 **아주 큰 정수**(일반 `number`의 안전 정수 범위를 넘는 값)를 **정확히 표현**하기 위한 타입.
> **한 문장 요약**: `2**53 - 1`을 넘는 정수도 **정밀도 손실 없이** 다룰 수 있다.

### 왜 필요한가

- JavaScript의 `number`는 IEEE 754 **배정밀도 부동소수점** 형식을 사용하므로
  **안전한 정수 범위**가 `-(2**53 - 1)` ~ `2**53 - 1`로 **제한**된다.
- 이 범위를 넘는 정수는 **연산 시 미세한 오류**가 발생할 수 있다.

```javascript
console.log(9007199254740991 + 1 === 9007199254740991 + 2); // true
console.log(9007199254740991 + 2); // 9007199254740992
console.log(9007199254740993); // 9007199254740992
```

- 위처럼 **큰 정수 리터럴/연산**에서 **정밀도 손실**이 드러난다.

### BigInt 만들기

```javascript
console.log(9007199254740993n); // 9007199254740993n  (리터럴 뒤에 n)
console.log(BigInt('9007199254740993')); // 9007199254740993n  (문자열을 BigInt로)
```

- 정수 리터럴 뒤에 **`n`** 을 붙이거나, `BigInt('...')` **문자열**을 넘겨 생성한다.
  (숫자 리터럴로 크게 써버리면 먼저 `number`로 해석되어 **정밀도 손실**이 날 수 있어 문자열 변환 예시를 사용)

### 주의사항

```javascript
// 소수는 BigInt로 쓸 수 없다.
// console.log(1.5n); // SyntaxError: A bigint literal must be an integer.

// 나눗셈 결과는 소수점 아래를 버리고 정수(BigInt)로 나온다.
console.log(10n / 6n); // 1n
console.log(22n / 4n); // 5n

// BigInt 끼리만 직접 연산 가능. 다른 타입과 섞으려면 명시적 변환 필요.
// console.log(3n * 2); // TypeError: Cannot mix BigInt and other types...
console.log(3n * 2n); // 6n
console.log(Number(3n) * 2); // 6
```

- `BigInt`는 **정수용**이므로 **소수 표현 불가**.
- `BigInt` 연산 결과는 **정수(BigInt)**.
- **타입 섞기 금지** → 필요 시 `Number(...)` 등으로 **명시적 변환**.

> 참고: JavaScript 수의 내부 표현 관련 배경은 아래 링크를 보세요 —
> [IEEE 754](https://ko.wikipedia.org/wiki/IEEE_754), [배정밀도 부동소수점 형식 숫자체계](https://ko.wikipedia.org/wiki/%EB%B6%80%EB%8F%99%EC%86%8C%EC%88%98%EC%A0%90)

## 핵심 요약

- **Symbol**: 설명이 같아도 **값은 항상 유일**하다 → 동등 비교는 언제나 `false`.
- **BigInt**: `number`의 **안전 정수 범위**를 넘어서는 **큰 정수**를 **정확히** 다룰 수 있다.
- BigInt는 **정수 전용**, **소수 불가**, **BigInt끼리만 연산**(필요 시 명시적 변환).
- 큰 정수에서 보이는 **정밀도 손실 문제**를 BigInt가 **해결**해 준다.
